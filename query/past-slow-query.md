# 怎样追查已经结束的慢 SQL

**操作说明**

作业已结束时，当前活跃会话视图不能还原当时的计划。先找当次执行的提交、开始和结束时间，可区分排队时间与执行时间。

用执行历史或当时已保存的慢日志确定查询和时间窗，再与同窗的队列、锁、节点和存储监控对齐。若历史采集没有开启，只能记录现有证据支持的范围。今天重新生成的计划可用于对照，却不能代表当时执行的计划。

为下一次偶发问题采集计划时，先在相同版本验证输出位置、开销和轮转。带实际运行统计的计划会执行工作负载。某次开启自动计划记录后还曾遇到独立的后端退出问题，见[自动记录计划时后端退出](../stability/auto-explain-exit.md)。
