# 开启自动归档和清理后存储 I/O 升高

**待验证**

在已有自动合并的环境中，开启自动归档和清理后，后台任务持续运行，数据节点出现较高读吞吐。哪类任务贡献了多少 I/O 仍待确认。

Archive 处理提交历史。对支持的表，归档后若有可合并文件，可能派发 Compact。没有合并候选时也可能按配置请求 Clean。Compact 涉及重读和重写，Clean 涉及删除过期文件。多个后台任务可以交错，原来就在队列里的任务也可能先完成。

先选一张表，对齐请求类型、发起来源、实际执行时间和存储端读写、删除操作。节点总读吞吐无法区分业务扫描与 Compact。删除次数也不能换算成磁盘读写字节。把首次处理历史积压的时段与积压消退后的时段分开比较，再决定维护窗口。
