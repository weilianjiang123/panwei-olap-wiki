# JDBC 停止读取后会话持续等待 ClientWrite

**测试已验证**

当客户端停止从网络读取结果、但物理连接仍保持打开时，协调节点可能持续等待 ClientWrite，执行节点也会等待读者。在测试中，关闭对应物理连接后，两侧会话都被清理。

长时间不调用结果集的下一行，与停止从网络读取是两种情况。对照中，取数任务因内存不足退出、应用进程仍存活并持有连接，复现了持续等待。没有证据把它概括为 JVM 一直在进行垃圾回收。

取消或终止接口返回成功表示请求已发出。验收要同时看协调节点和执行节点上对应的会话是否消失。2.4.7 测试构建中，修正后通过普通 TCP 重测，即使客户端还活着，两侧会话也能在终止后退出。实际部署是否包含该修正需查发布版本。另见 [SSL 握手问题](ssl-handshake.md)。
